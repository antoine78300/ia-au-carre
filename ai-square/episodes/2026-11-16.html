Full transcript

Maya: Good morning and welcome to AI Squared, the podcast that breaks down artificial intelligence for you every single day. Today is Monday, November 16th, 2026, and we are diving into a world where AI agents are taking on more and more mission-critical tasks. But are we right to trust them? Security, governance, new tools, academic research — we've got a packed show. Get comfortable, let's get into it.

Maya: Ryan, good morning! Let's jump straight to the biggest story of the day, and honestly it's a little unsettling: the security of AI agents. VentureBeat just ran a pretty alarming piece on MCP servers. Can you walk us through what's going on?

Ryan: Good morning, Maya. Yeah, this is absolutely the story that deserves our full attention today. MCP — Model Context Protocol — is essentially the protocol that lets an AI agent talk to external tools: databases, APIs, third-party services. The whole idea is to give the agent the means to actually act in the real world.

Maya: And the problem is that this protocol can be compromised?

Ryan: Exactly. And this is where the VentureBeat piece gets really interesting. OWASP — the organization that catalogs major security risk categories — has identified ten types of risks specific to AI agents. What this article reveals is that only two of those ten risks have anything to do with the text the agent directly reads. The other eight — and this is where it gets concerning — live in the infrastructure itself: access credentials, permission scopes, identity management. And the MCP protocol has no built-in guardrails for any of that.

Maya: So in practical terms, if an MCP server gets compromised, the agent can be manipulated into doing things it shouldn't, using tools it's been fully authorized to access?

Ryan: That's exactly it. Picture an agent that you've given access to your internal messaging system and your customer database. If the MCP server orchestrating those tools gets infiltrated, an attacker can trick the agent into using those access rights maliciously — exfiltrating data, sending fraudulent messages — all while operating under the agent's legitimate permissions. The agent just follows instructions, because it has no way to tell the difference between a legitimate command and one injected by a bad actor.

Maya: And this isn't some hypothetical scenario, because AI agents in enterprise environments are already very much a reality.

Ryan: Absolutely. Gartner is predicting that 40 percent of enterprise applications will incorporate AI agents by the end of 2026. We're talking about massive adoption, in contexts where the stakes are high. Securing agentic infrastructure is no longer an academic research topic — it's an operational emergency.

Maya: That really sets the stage. We'll actually come back to governance around all of this in our frameworks segment. But first, let's talk about some of the new tools and frameworks that have been landing recently. Ryan, there were several interesting announcements over the past few days.

Ryan: There were, and let's start with one that really caught my eye: Vercel Labs open-sourced a UI SDK along with something called an Agent Bridge on November 13th. Both are released under the Apache 2.0 license, so completely free to use and build on.

Maya: Vercel is primarily known as a web deployment platform. What do they bring to the AI agent space?

Ryan: Up until now, when an AI agent needed to interact with a web interface — click a button, fill out a form, navigate through an application — you usually had to resort to DOM scraping, which means parsing the raw page code to find interactive elements. It's brittle, it breaks every time the design changes, and it's a nightmare to maintain.

Maya: And this SDK changes that?

Ryan: Completely. It provides more than fifty headless behaviors — think predefined, stable, accessible interactions — that allow an agent to manipulate a web interface programmatically and reliably. The agent no longer needs to decode the visual structure of the page; it has a clean abstraction layer to work with. It's the first formalized open-source infrastructure for this kind of orchestration.

Maya: Let's move on to governance now, because that's really the throughline of today's show. There's a piece from CDOTrends that lays out a very structured approach to governing autonomous agents.

Ryan: Right, and it's a direct response to the security issues we were just talking about. The article draws on two reference frameworks: OWASP 2026 and an agentic governance framework developed by Singapore. The core idea is to classify an agent's actions along two dimensions: severity and reversibility.

Maya: So you're essentially assigning risk levels to every type of action?

Ryan: Exactly. Low-risk actions — looking something up, drafting a piece of text — can be fully automated without any human oversight. Moderate-risk actions require human approval before they execute. And high-risk actions are simply blocked by default.

Maya: It's almost like an org chart, but for AI agents.

Ryan: That's actually the exact metaphor used in the article. The agent has a defined role, clearly scoped responsibilities, and an explicit escalation path. And the article makes an important point: this governance framework has to be defined at the role and architecture level, not just baked into the agent's prompt. Because a prompt can be manipulated, as we just saw with compromised MCP servers.

Maya: There's also a piece about context window management. It's a pretty technical subject, but apparently it's critical when you're running agents in production.

Ryan: It's a very real practical problem. When an AI agent is working on a long task — analyzing a large document, managing a multi-step project — it accumulates information in what's called the context window, essentially the model's active working memory. And that window has a hard size limit. When it fills up, tasks fail or performance degrades significantly.

Maya: And there are techniques to handle that?

Ryan: There are. The Startup Fortune article documents two main approaches. The first is context editing, a technique developed by Anthropic back in September 2025, which lets you clean and compress the context window while a task is still running. The second is using sub-agents with summaries: instead of one agent accumulating everything, you break the work into specialized agents that hand off concise summaries rather than full histories.

Maya: And that actually makes a meaningful difference in performance?

Ryan: The numbers are striking. These techniques cut token consumption by 84 percent and improve workflow performance by 39 percent compared to naive deployments. That's the difference between an agent that can go the distance and one that just falls apart after an hour of work.

Maya: Let's shift to research now. There are two recent academic papers worth stopping on.

Ryan: The first comes out of the University of Illinois. A preprint published on November 12th presents a two-agent architecture for conducting interactive oral exams at scale.

Maya: Oral exams run by AI agents? That's a kind of wild idea.

Ryan: It is, and yet it's fascinating from a technical standpoint. The architecture uses two collaborating LLM agents: one asks the questions, engages with the student, and adapts based on their responses; the other plays a supervisory and evaluation role. The goal is to replicate the richness of a human oral exam — the follow-up questions, the back-and-forth — without the constraint of examiner fatigue. And critically, at a scale that would simply be impossible with humans alone.

Maya: And then there's AskALCF, coming out of Argonne National Laboratory.

Ryan: Yes, that one was presented at SC26 — the major international supercomputing conference — on November 11th. AskALCF is an agentic framework built for user support on supercomputers. What makes it remarkable is its automated feedback loop: the system continuously analyzes user interactions in production, identifies the root causes of failures — whether it's a retrieval problem, insufficient documentation, a poorly formulated prompt, or unexpected model behavior — and improves itself accordingly.

Maya: So it's an agent that gets better by analyzing its own mistakes?

Ryan: Exactly. And in the HPC context — High Performance Computing — that's especially significant, because the reliability stakes there are extreme. It's the first documented agentic orchestration system for critical computing infrastructure with this kind of continuous improvement loop.

Maya: Impressive. Let's wrap up with industry impact. What's taking shape on the model and production architecture side?

Ryan: Two things to highlight. First, on the Google side, there's some interesting documentation around the deployment of three specialized Gemini 4 models — named Argon, Carbon, and Hydrogen — applied to scientific and engineering tasks. What's notable is the approach: rather than relying on one generalist model, these three models collaborate through a native command built into existing agent products, with formal verification integrated in. The goal is to replace or supplement human review on precise technical tasks.

Maya: So we're moving from a single model to a team of specialized models that divide up the work.

Ryan: That's the broader shift we're seeing right now. And the second point comes from academic research with Skill Adapter, published November 12th by researchers from Nanjing and Jiangnan universities. It's an open-source framework that applies classic software engineering principles — dependency injection, aspect-oriented programming — to agentic orchestration.

Maya: And what does that look like in practice?

Ryan: The idea is to decouple an agent's reusable skills — knowing how to run a search, knowing how to summarize a document — from the customizations specific to each user or context. With a dynamic routing system, the agent selects the right skills for the task at hand. It avoids performance degradation on long tasks, because skills don't pile up in a disorganized way inside the context.

Maya: And it's essentially taking the lessons of traditional software engineering and applying them to a completely new context.

Ryan: That's what strikes me most about this paper. We're starting to see a genuine engineering discipline emerge around AI agents — with patterns, architectural principles, established best practices — the same way we saw it develop in software engineering decades ago. That's a real sign of maturity.

Maya: To wrap up today's episode, what comes through loud and clear is that the era of autonomous AI agents is here — Gartner is calling for 40 percent of enterprise applications by year's end — but we're still in the process of building the foundations to make them safe and reliable. MCP server security, risk-tiered governance, context window management, multi-agent architectures: all of these threads converge on the same fundamental question. How do you give agents more autonomy without losing control?

Ryan: And the answers are coming from everywhere at once — companies like Vercel and Google, universities in Illinois, in China, at Argonne — which shows just how global and urgent this challenge has become.

Maya: Ryan, thank you so much for all of this analysis. And thank you to everyone listening for sticking with us through the whole show. AI Squared will be back with a brand new episode tomorrow. See you then!
